## 1. Routing Matrix

| وضعیت محتوا | ساختار اصلی | Storytelling |
|---|---|---|
| پاسخ مدیریتی مستقیم | Answer → Evidence → Implication → Decision | کم |
| مشاهده عملیاتی | Scene → Friction → Reframe → Decision | زیاد |
| تصمیم واقعی | Problem → Options → Risk → Decision → Result | متوسط تا زیاد |
| داده | Delta → Meaning → Decision | فقط در صورت وجود Case |
| آینده‌پژوهی | Signal → Why it matters → Decision now | کم تا متوسط |
| آزمایش | Hypothesis → Test → Evidence → Learning | متوسط |
| تغییر باور | Old belief → New evidence → Correction | زیاد |
| Framework | Problem → Model → Example → Use | کم |

قاعده: ساختار باید از Job و Evidence انتخاب شود؛ نه از علاقه به Storytelling.

## 2. LinkedIn

نقش: مرجعیت فکری مدیریتی و B2B.

پیش‌فرض:

**Hook → Context → Evidence → Reframe → Decision**

### LinkedIn Text

- یک Claim اصلی.
- Context در 1 تا 3 پاراگراف اول روشن شود.
- Evidence زود وارد شود.
- پاراگراف‌ها کوتاه و قابل استخراج باشند.
- جمله قابل نقل داشته باشد.
- CTA تصمیمی باشد.
- ایموجی پیش‌فرض صفر باشد.

### Narrative LinkedIn

روایت فقط وقتی استفاده شود که تجربه یا تصمیم واقعی وجود دارد.

ساختار:

**Scene → Anomaly → Evidence → Meaning → Executive Reframe → Decision**

داستان نباید جای تحلیل مدیریتی را بگیرد.

### Citation-oriented LinkedIn

- سؤال دقیق در ابتدا روشن شود.
- Answer Block در نسخه Canonical وجود داشته باشد.
- Keyword اصلی زود استفاده شود.
- اصطلاحات Canonical ثابت بمانند.
- Open Loop نباید Answer-first را تخریب کند.

## 3. Short Video / Reels / Shorts

نقش: یک ایده در کمترین زمان.

ساختار پایه SSOT:

**Hook → One Insight → Proof → Takeaway**

در Executive Video طولانی‌تر:

**Hook → 3 Points → Example → Conclusion**

### قواعد

- جمله اول بدون مقدمه وارد مسئله شود.
- یک ویدئو فقط یک پیام اصلی داشته باشد.
- حضور واقعی یوسف بر B-roll عمومی اولویت دارد.
- اسکریپت نباید اجرای خشک ایجاد کند.
- Re-hook فقط وقتی استفاده شود که Beat جدید واقعی وجود دارد.
- زیرنویس باید Context مستقل داشته باشد.
- پایان باید یک Takeaway یا Decision روشن داشته باشد.

## 4. Instagram Caption

نقش: Context و Insight برای محتوای بصری.

ساختار:

**Hook سریع → Context کوتاه → Insight → CTA ساده**

Caption نباید Transcript کامل ویدئو باشد مگر ضرورت داشته باشد.

## 5. X / Twitter

نقش: آزمایش Claim و POV.

ساختار:

**Claim → Evidence/Reason**

Thread:

- هر پست یک وظیفه داشته باشد.
- Open Loop محدود باشد.
- Punchline جای Evidence را نگیرد.

## 6. Telegram

نقش: Context و عمق.

ساختار:

**تیتر → خلاصه → Context → Evidence → Interpretation → Action**

روایت می‌تواند طولانی‌تر باشد، اما Answer باید دیر نشود.

## 7. Website / Blog

نقش: Canonical Authority.

ساختار:

**Question/Problem → TL;DR → Definition → Evidence → Analysis → Decision → FAQ**

Storytelling فقط به‌عنوان Case یا Example استفاده شود.

AI Search Readability بر Open Loop اولویت دارد.

## 8. YouTube Long-form

نقش: Framework و Case Study.

ساختار:

**Promise → Problem → Framework → Evidence → Example → Decision**

Narrative arc مجاز است، اما Framework باید زود معرفی شود.

## 9. Podcast / Interview

هر پاسخ مهم:

- یک جمله مرکزی
- حداکثر سه دلیل
- یک شاهد
- یک محدودیت یا Context

پرسش باید پاسخ قابل نقل بسازد.

## 10. Cross-platform Invariants

این موارد ثابت می‌مانند:

- Fact
- Position
- Number
- Entity
- Date
- Certainty level
- Core Claim

این موارد قابل تغییرند:

- Hook
- Length
- Example
- Order
- Intimacy
- CTA
- Visual treatment
